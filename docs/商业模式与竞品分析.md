# 轻迁 MoveLite：商业模式与竞品分析

调研日期：2026-10-22。本文记录产品定位、公开竞品能力和待验证的商业假设，不代表市场规模、付费需求或营收已经得到验证。

后续使用场景讨论暴露了关键风险：用户可能在整理现场更快做出决定，事前登记的成本反而高于方案收益。本文保留原有调研与假设；最新产品结论以 [需求复盘](需求复盘.md) 为准，不能将下文价格或定位视为已经成立的商业模式。

本仓库提供 v1.0.0 可运行 MVP。源码：https://github.com/xf-png/movelite-ai ；演示：https://xf-png.github.io/movelite-ai/ 。已完成 27 项自动检查与 11 项真实 Chrome 使用流程，证据见 [验证记录](验证记录.json)；生产发布状态见仓库 Actions。原 CiteMind 为独立项目。

## 1. 解决什么问题

搬家前，个人用户需要在有限的新家空间、可用处置时间和搬运费用之间做取舍。物品清单能够回答“我有什么”，但用户仍需要判断“哪些带走、哪些转让、哪些捐出，以及先做什么”。

轻迁将这个阶段做成一个决策工作台：确认物品信息，设置搬家约束，比较三套可行方案，锁定自己不愿改变的决定，再执行行动清单。主要面向毕业跨城搬家、租房换到小户型、临近搬家日期的个人用户。

这里的产品机会是一项待验证的判断：用户是否愿意为更快做出可执行的取舍付费。它不是“市场上没有同类产品”的结论。

## 2. 已有产品与竞争边界

| 产品 | 官方已公开的能力 | 对轻迁定位的影响 |
| --- | --- | --- |
| [Sortly 家庭库存](https://www.sortly.com/solutions/home-inventory-software/) | 记录物品照片、位置、尺寸和价值，生成条码或 QR，导入清单，追踪物品及汇总。 | 家庭物品登记、分类、标签和导出已经很成熟。 |
| [MovingBox](https://movingbox.ai/) | AI 识别图片中的物品，自动按房间和类别整理，提供保险用途的重置价值估计及导出。 | “AI 识物加库存表”不足以形成差异；重置价值也不能直接当作二手成交收入。 |
| [MOVINGBOXES](https://www.movingboxes-app.com/en/) | 搬家清单、标签、图片 AI 识别、箱子状态、物品价值、体积计算和协作。 | 仅增加体积统计或搬箱跟踪仍然高度相似。 |
| [Clutterfree](https://clutterfree.com/) | 个性化整理路线、进度、捐赠记录和每日挑战；官网提供订阅方案。 | 一般断舍离任务清单和激励机制已有产品覆盖。 |

轻迁拟强调的是：**在容量和时间约束下生成可解释的组合方案，并让用户锁定、修改和重算。** 这是基于上述页面做出的产品定位推断，不是首创声明。

## 3. 三个具体使用场景

### 毕业跨城搬家

新租屋空间有限，部分旧家具可以转让。用户录入物品、确认体积和预期转让金额，并填写实际询到的车型报价，比较“多留一点”和“少花一点”。展示预计收入与支出，避免将尚未成交的转让直接记成已省下的钱。

### 换到小户型

用户锁定纪念品和必需物品为保留，调整目标容量，查看其余物品的组合。如果锁定物品已超过容量，应明确提示当前约束无可行方案，交由用户修改，不能偷偷取消锁定或隐藏超限。

### 临近日期急搬

用户减少可用处置时间，比较“快一点”方案，查看哪些转让需要拍照、沟通和交接，哪些动作能更快完成。行动清单可导出到日历，但日历事件不表示已经预约买家、捐赠机构或搬家服务。

## 4. 本版的业务闭环与实现边界

1. **录入并确认。** 自然语言规则导入一律是草稿；用户确认后才进入方案。可选本地 BGE q8 模型用于语义分类，模型、WASM 和分词器首次从本站加载约 47 MB。分类建议不等于正确答案，不自动生成尺寸、价格或成交概率。
2. **设置约束。** 容量最多 10,000 L，处置时间最多 720 分钟，最多 40 条整组物品。每条物品作为一组整体决策；想拆分时应先拆成不同条目。
3. **求解和比较。** 使用按 10 L、5 分钟保守分档的二维多选择动态规划，比较“多留一点”“少花一点”“快一点”。保守分档会使结果偏向不超出真实上限，也可能排除实际可行的边界组合；不能称为未离散原问题的全局最优。
4. **费用解释。** 运费按用户输入的三档车型容量和固定报价计算；同一车型内减少一件物品不自动带来按比例节省。所有金额都是输入假设下的计划值，不是平台行情或搬家公司承诺。
5. **执行和记录。** 用户可锁定动作、重新计算、标记执行进度，分别记录预计转让收入和实际收入。转让文案是模板，须自行核对后使用，不会自动发布到交易平台。
6. **保存与导出。** 可选浏览器本地保存、JSON 备份、Markdown 方案和 ICS 行动清单。清除浏览器数据或换设备前需要自行备份；当前没有家庭云同步、交易撮合或实际收款系统。

## 5. 收费假设

搬家通常是阶段性需求，因此先验证按项目收费，而不是直接假定用户愿意长期订阅。

| 待测试方案 | 候选价格 | 要验证的问题 |
| --- | --- | --- |
| 免费体验 | 免费 | 用户能否完成信息确认并理解第一套可行方案，是否愿意主动修改约束重算。 |
| 单次搬家基础项目 | ¥9.9/次，候选测试价 | 多情景比较和可交接的行动计划是否值得一次付费。 |
| 单次搬家完整项目 | ¥19.9/次，候选测试价 | 更复杂的方案对比、后续家庭协作等能力是否能提高实际购买意愿。 |

这两档价格不是已上线套餐；家庭协作等内容也是后续假设，不能在当前页面假装已实现。现阶段不接入支付、不展示虚构订单或成交人数，也不将普通导出功能本身当作已经成立的付费壁垒。

后续可测试租赁服务、整理师或搬家服务渠道的合作分发。服务合作与物品去留评分应独立，用户决定是否联系服务方；本版不自动向第三方发送联系方式或家庭物品数据。

## 6. 如何验证，而不是虚构收益

先招募近期确有搬家计划的用户，观察其使用自有物品完成一次真实决策；再对候选付费点进行访谈或明确告知的价格测试。下列是指标定义和测试计划，没有填入未经测量的结果。

| 指标 | 记录方式 | 解释边界 |
| --- | --- | --- |
| 首次方案完成率 | 完成物品确认并生成可行方案的用户数 / 开始录入用户数。 | 需要报告样本来源和数量，不能等同于留存。 |
| 首次价值耗时 | 从开始录入到首次确认一套方案的时间。 | 区分手动录入、规则草稿、模型首次下载和已缓存模型。 |
| 建议修改情况 | 记录被用户锁定、修改或否决的动作及原因。 | 修改少不必然意味着推荐好，也可能是用户未理解。 |
| 执行完成率 | 在用户设定截止日期前完成的行动 / 已确认行动。 | 需记录未完成原因，不把导出计划当作完成搬家。 |
| 付费意愿 | 记录对具体套餐的选择，以及未来实际启用支付后的真实购买。 | “愿意试试”与真实成交分别记录。 |
| 计划与实际差异 | 比较输入报价、最终运费、预计收入与实际收入。 | 不能把计划中的假设金额宣传成节省成果。 |

技术验收还应覆盖：人工锁定不被更改、约束冲突被明确报告、真实容量和时间不超限、分档边界、三档运费切换、实际收入不被预估覆盖，以及异常备份不会破坏已有资料。实现及测试完成前不公布通过数量、性能指标或收益提升。

## 7. 当前结论

本项目已实现约束优化、AI 分类与执行记录，可用于展示工程能力。作为消费产品，事前登记是否比现场决定更省事这一前提没有得到验证，现有用户反馈已经对该前提提出具体反例。市场需求、价格、渠道及付费转化仍无真实数据支持；应先验证实际使用成本，再讨论商业化。详见需求复盘。
